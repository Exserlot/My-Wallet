# Android App Flow

## Navigation

แถบนำทางหลักของ MVP มี `ภาพรวม`, `รายการ`, `วางแผน` และ `กระเป๋า` โดยแท็บวางแผนรวม Monthly Budget, Fixed Cost และ Shopping List ไว้ด้วยกัน เพื่อไม่เพิ่มเมนูหลักจนแน่นเกินไป

## Overview

ใช้แนวทาง A จาก prototype เป็นโครงสร้างหลัก โดยเรียงข้อมูลดังนี้:

1. ยอดรวมและทางลัดไปยัง Wallet
2. สถานะ Monthly Budget ของ Budget Cycle ปัจจุบัน
3. เรื่องที่ต้องจัดการวันนี้จากแนวทาง C เช่น Fixed Cost ใกล้ครบกำหนดหรือ Budget Allocation ใกล้เต็ม
4. Transaction ล่าสุด

ปุ่มเพิ่ม Transaction ต้องมองเห็นและเข้าถึงได้ง่ายจากหน้าหลัก

## Transaction Entry

ใช้แนวทาง B เป็น flow บันทึกรายการ โดยให้การกรอกด้วยมือเป็นเส้นทางหลัก:

1. เลือก Expense, Income หรือ Transfer
2. กรอกจำนวนเงิน
3. เลือกหมวดและ Wallet พร้อมตรวจวันเวลา
4. ตรวจข้อมูลและยืนยันบันทึก

Bank Slip เป็นทางเลือกสำหรับช่วยกรอกข้อมูล ผู้ใช้ต้องตรวจและยืนยันก่อนสร้าง Transaction เสมอ

การนำเข้า Bank Slip รองรับการเลือกรูปหลายรูปในครั้งเดียว โดยแต่ละรูปต้องอ่าน QR และ on-device OCR ตรวจรายการซ้ำ และรายงานผลแยกกัน รูปที่สำเร็จต้องไม่ถูกขัดขวางด้วยรูปอื่นที่อ่านไม่ได้ เมื่อจำนวนเงิน วันเวลา และ Wallet ครบ ผู้ใช้สามารถยืนยันสร้าง Expense โดยปล่อย Expense Category เป็น `ยังไม่ระบุ` และกลับมาจัดหมวดภายหลังได้ รายการที่ยังไม่ระบุต้องมองเห็นและกรองได้จากหน้ารายการ

## Planning

แท็บวางแผนมีหน้ารอง `งบเดือน`, `Fixed Cost` และ `ของที่ต้องซื้อ`

### Shopping List

- Shopping List เป็น Wishlist ต่อเนื่องข้ามเดือนและไม่ผูกกับ Budget Cycle
- Planned Purchase บังคับเฉพาะชื่อสินค้า ข้อมูลเสริมคือจำนวน ราคาประมาณ Expense Category ร้านค้า หมายเหตุ และความสำคัญ
- ราคาประมาณใช้เป็นข้อมูลอ้างอิงเท่านั้น ไม่กันงบ ไม่ลด Budget และไม่หัก Wallet
- ผู้ใช้เลือก Planned Purchase หลายรายการที่ซื้อพร้อมกันเพื่อสร้าง Expense หนึ่งรายการ แล้วตรวจยอดจริง Wallet วันที่ หมวด และ Bank Slip ก่อนยืนยัน
- รายการที่ซื้อแล้วมีสถานะสำเร็จ รายการที่ไม่ได้ซื้อยังอยู่ต่อ และผู้ใช้ยกเลิกหรือ Archive ได้
- Budget และยอด Wallet เปลี่ยนเฉพาะเมื่อสร้าง Expense จริง
